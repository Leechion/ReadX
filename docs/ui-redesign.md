## 0. 给实施者的约束（先读）

1. **只改表现层**：CSS、JSX 结构、展示组件。`api/`、`hooks/`（除 `useTheme.ts`）、`lib/` 里的业务逻辑、数据流、存储键都不要动。
2. **保留主题机制**：主题仍然写在 `<html data-theme="light|dark|paper">`，`ThemeChoice` 的四个值（含 `system`）不变。`LatexEditor.tsx` 会监听 `data-theme` 来切换 Monaco 主题，这个契约要保留。
3. **保留动态类名**：批注类名是运行时拼出来的，比如 `ann-highlight-amber`、`ann-underline-*`、`ann-question-*`、`ann-color-*`。这些不能改名，颜色只能通过 token 调整。
4. **改类名前先搜引用**：先在 `src/` 和测试里全局搜索（项目依赖 `fake-indexeddb`，说明有测试）。有引用的类名，要么保留，要么同步修改。
5. **不在范围内**：Alt 轮盘（`LauncherWheel`）的交互形态，只做 token 接入，不改外观。摸鱼界面纳入重设计（见 6.14），但挂件图片和角色素材不换、不改，权利归属不变。
6. **macOS 端**：先确认 `macos/` 是否有一份独立的前端拷贝。有的话，先只改 Windows 端，最后再同步。
7. **每个阶段结束都要跑**：
   ```
   cd windows/apps/web
   npm run typecheck
   npm run build
   ```
   然后在浅色、深色、纸张三个主题下，分别用 1100 / 1440 / 1920 三种宽度截图，和改动前对比。

### 样稿使用说明

- **token 命名对照**：样稿里的变量用 `--page-` 前缀，实施时换成本文第 3 节的正式名，规则如下：
  - `--page-canvas`、`--page-surface`、`--page-sunk`、`--page-hover`、`--page-raised`、`--page-line`、`--page-ink`、`--page-accent` 等，换成同名的 `--color-*`。其中 `raised` 对应 `--color-surface-raised`，`hover` 对应 `--color-surface-hover`，`sunk` 对应 `--color-surface-sunk`。
  - `--page-elev-*` 换成 `--elev-*`，`--page-r-*` 换成 `--radius-*`，`--page-t1…t4` 换成 `--color-entity-1…4`。
- **样稿是静态 HTML**：可以照抄它的 CSS 数值，但不要把它的 DOM 结构原样搬进 React。组件结构按现有代码和第 5 节来做。
- **示例数据**：样稿里的论文、数字、日历、统计都是编的，不要当成需求。
- **图标**：样稿里的图标是手写的简化线条，实施时换成项目里已经在用的图标。服务商 Logo 复用 `providerLogos.tsx`。
- **知识图谱**：样稿里的点云用 Canvas 2D 画成，只是为了演示外观。正式实现仍然用现有的 three.js。
- **验收方式**：每个阶段完成后，把三个主题下的截图和样稿对应位置并排对比。

## 1. 现状诊断

依据：`src/index.css`、组件目录、README 截图。

| 问题 | 证据 | 影响 |
|---|---|---|
| 样式集中在一个巨型文件 | `index.css` 共 3266 行、约 271 KB，另有 10 个零散的组件 CSS | 难维护，改一处容易连带别处 |
| token 定义了却没人用 | `--radius-*`、`--type-*`、`--space-*` 都已定义，但 `var(--radius-md)` 只用了 12 次 | 视觉不统一 |
| 颜色硬编码多 | CSS 里有 290 处十六进制颜色字面量，其中 `#fff` 就有 30 处 | 深色、纸张主题容易出现漏网的亮块 |
| 字号碎片化、偏小 | 出现了 20 多种字号，包括 9px、10px、10.5px、11.5px、12.5px。其中 11px 有 163 处，10px 有 92 处 | 桌面端长时间阅读吃力，层级也不清楚 |
| 圆角值太多 | 4、6、7、8、9、10、11、12、14px 混用 | 界面"差不多但不一样"，显得不精致 |
| 阴影各写各的 | 71 处 `box-shadow`，大多是手写值 | 层级关系混乱 |
| 摸鱼界面自成一套 | `components/slack/slack.css` 共 3130 行，有 53 处硬编码颜色，字号低到 9px、9.5px | 和主界面视觉脱节，深色、纸张主题下容易漏色 |
| 数字字体不一致 | `Instrument Sans` 把 0–9 和全角数字的 `unicode-range` 指向了 Times New Roman | 无衬线界面里突然出现衬线数字，统计和进度数字很突兀 |

**要保留的优点**：墨绿强调色的品牌识别度、纸感中性色、三主题加跟随系统的能力、4px 间距档位、"批注不只靠颜色区分"的做法。

## 2. 设计方向：「安静的书房」

一句话：**内容是主角，界面退到后面。** ReadX 的用户一坐就是几个小时，所以界面应该低噪声、结构清楚、不抢注意力，只在需要的时候出现。

四条原则：

1. **克制的颜色**：中性色负责结构，墨绿只用在"当前状态"和"主要操作"上。每屏的强调色面积不超过约 5%。
2. **清楚的层级**：用字号、字重、留白区分层级，少用边框和底色。
3. **一致的外壳**：九个工作区共用同一套框架，结构是 导航栏 → 上下文侧栏 → 主画布 → 检查器。
4. **阅读优先**：阅读器默认沉浸，工具按需出现；译文排版按"能读一本书"的标准来做。

### 3.2 字体

```css
--font-sans: 'Instrument Sans', 'PingFang SC', 'Microsoft YaHei UI', 'Microsoft YaHei', system-ui, sans-serif;
--font-reading: 'Source Han Serif SC', 'Noto Serif SC', 'Songti SC', 'SimSun', Georgia, serif; /* 译文阅读，可选 */
--font-mono: 'JetBrains Mono', 'Cascadia Code', Consolas, monospace;
```

- **去掉数字指向 Times New Roman 的 `@font-face` 覆盖**。实施前先查一下 git 记录或问项目负责人当初为什么这样做。如果是为了公式或页码对齐，就只在那几个局部保留衬线数字。
- 统计、进度、页码、计数统一加 `font-variant-numeric: tabular-nums;`。
- 译文窗格默认仍用无衬线。设置里加一个「译文字体：无衬线 / 衬线」选项，只切换 `--font-reading`。

### 3.3 字号阶梯（收敛成 7 档）

| Token | 字号 / 行高 | 用途 |
|---|---|---|
| `--text-2xs` | 11 / 16 | **仅限**徽标、计数角标，不用于正文或说明 |
| `--text-xs` | 12 / 18 | 辅助说明、时间戳、元信息 |
| `--text-sm` | 13 / 20 | 界面默认：列表、按钮、表单 |
| `--text-base` | 14 / 22 | 面板正文、AI 回答 |
| `--text-md` | 16 / 26 | 卡片标题、阅读正文（可调） |
| `--text-lg` | 20 / 28 | 区块标题 |
| `--text-xl` | 24 / 32 | 页面标题 |
| `--text-2xl` | 32 / 40 | 空状态、引导大标题（少用） |

**下限规则：说明文字不小于 12px。** 现有的 9px、10px、10.5px 一律升到 12px；11.5px、12.5px 归到最近的一档。全大写的英文小标题（overline）可以用 11px，字距 `.06em`。

字重只用三档：400 正文、500 标签和按钮、600 标题。不用 700。

### 3.4 圆角、间距、层级、动效

```css
--radius-xs: 4px;   /* 徽标、小标签 */
--radius-sm: 6px;   /* 小按钮、输入框内嵌元素 */
--radius-md: 8px;   /* 按钮、输入框、菜单项 */
--radius-lg: 12px;  /* 卡片、面板 */
--radius-xl: 16px;  /* 对话框、浮层 */
--radius-pill: 999px;

/* 间距：沿用 4px 档位 --space-1…--space-8，再补 --space-10: 40px; --space-12: 48px; */

--elev-0: none;                                                    /* 平铺，靠分隔线区分 */
--elev-1: 0 1px 2px rgb(20 30 25 / .05);                           /* 卡片 */
--elev-2: 0 4px 16px -4px rgb(20 30 25 / .12), 0 0 0 1px var(--color-line); /* 菜单、气泡 */
--elev-3: 0 24px 48px -16px rgb(20 30 25 / .28), 0 0 0 1px var(--color-line); /* 对话框 */
/* 深色主题：阴影几乎看不见，改用更亮的 surface-raised 加 1px 描边表达层级 */

--ease-out: cubic-bezier(.2, .8, .2, 1);
--ease-in-out: cubic-bezier(.65, 0, .35, 1);
--dur-fast: 120ms;   /* 悬停、按下 */
--dur-base: 180ms;   /* 展开、切换 */
--dur-slow: 260ms;   /* 侧栏、对话框进出 */
```

`@media (prefers-reduced-motion: reduce)` 下，所有过渡时长归零。摸鱼窗帘动画在这种情况下也直接切换，不播放。

## 4. 应用外壳（统一框架）

九个工作区都放进同一套框架，分别是 `library`、`reader`、`graph`、`reproduction`、`calendar`、`presentation`、`compare`、`latex`、`research`：

```
┌────┬──────────────┬──────────────────────────────────┬─────────────┐
│    │ 上下文侧栏     │  顶栏 48px：标题/面包屑 · 搜索 · 主操作 │             │
│ 导 │ 240px 可折叠  ├──────────────────────────────────┤  检查器       │
│ 航 │（书架/目录/    │                                  │ 320–440px   │
│ 栏 │  项目文件…）   │            主画布                  │ 可拖拽/可关闭 │
│ 56 │              │                                  │（AI/批注/详情）│
│ px │              │                                  │             │
└────┴──────────────┴──────────────────────────────────┴─────────────┘
```

- **导航栏（Activity Rail，56px）**
  - 顶部放 Logo，下面是各工作区图标，配悬浮提示和快捷键提示，底部放同步状态点、主题切换、设置。
  - 当前工作区：图标用强调色，左侧加一条 3px 竖线。
  - 把现在 `.app-header` 里的工作区切换、主题切换（`.theme-switch`）、导入按钮（`.global-import`）迁过来。导入是全局主操作，放在导航栏顶部，用醒目的「＋」按钮。
  - 实施时先把现有头部的所有入口列成清单，逐项迁移，不能丢功能。
- **上下文侧栏**：内容随工作区变化，比如书库放书架和筛选，阅读器放目录，LaTeX 放文件树。用 `Ctrl+\` 折叠。现有的 `.library-sidebar.collapsed` 逻辑可以复用。
- **主画布**：不再做成"浮起的卡片"（现在的 `.library-main` 有外边距、圆角和阴影），改成平铺，和侧栏之间用 1px 分隔线。这样信息区域更大，也更安静。
- **检查器**：放 AI 助教、批注列表、论文详情、处理任务详情。各工作区共用同一个组件壳，宽度会被记住。复用 `ResizeHandle.tsx`。
- **顶栏 48px**：现在的 `--bar-height` 是 64px，降到 48px。左边放标题或面包屑，中间放搜索，右边放 1–2 个主要操作。
- **窄窗口（< 1100px）**：检查器改成覆盖式抽屉，上下文侧栏默认折叠。

**可选增强（放到 P5 阶段）**：`Ctrl+K` 命令面板，能搜论文、切换工作区、执行常用命令。

## 5. 组件规范

建议在 `src/components/ui/` 下沉淀一组基础组件。可以是 React 组件，也可以是 CSS 类，二选一，但要统一。

| 组件 | 规格 |
|---|---|
| **Button** | 变体：`primary`（强调色底）、`secondary`（surface 底加 line-strong 描边）、`ghost`（无底，悬停显示 surface-hover）、`danger`。尺寸：`sm` 28px、`md` 32px（默认）、`lg` 40px。圆角用 `--radius-md`，字号 13 / 500。图标与文字间距 6px。合并现有的 `.precision-button` 等多套按钮。 |
| **IconButton** | 方形，尺寸 28、32、36。必须提供 `aria-label` 和悬浮提示。 |
| **Input / Textarea / Select** | 高 32px，底色 `surface-sunk`，边框 `line`；悬停时边框变 `line-strong`；聚焦时边框变 `accent`，外加 3px `--color-focus` 外环。 |
| **Segmented** | 用于「双语 / 原文 / 译文」、视图切换、主题切换。底色 `surface-sunk`，选中项是 `surface` 底加 `--elev-1`。 |
| **Tabs** | 下划线式，选中项 2px 强调色下边框，用于检查器和对话框内部。 |
| **Chip / Badge** | 状态标签，用 soft 底色加同色系文字，**必须带图标或文字，不能只靠颜色**，比如 ✓ 已翻译、◌ 排队中、⟳ 翻译中、! 失败。 |
| **Card** | `surface` 底，1px `line` 边框，`--radius-lg`，`--elev-1`。悬停时边框变 `line-strong`，**不上浮**，不做位移动画。 |
| **Menu / Popover** | `surface-raised` 底，`--elev-2`，`--radius-lg`，菜单项高 32px。 |
| **Dialog** | 宽度三档：480、640、880px。结构固定为 头部（标题 20px 加关闭按钮）/ 内容区（可滚动）/ 底栏（操作按钮靠右，主按钮在最右）。`--elev-3`，遮罩为 `rgb(0 0 0 / .32)`。统一 `AppDialog.tsx`、`ConfirmDialog.tsx` 以及各业务对话框的外壳。 |
| **Progress** | 线性进度条高 4px，圆角为 pill。环形进度 16px，用于列表行内显示。 |
| **Toast** | 右下角，`surface-raised` 底，最多同时 3 条，4 秒后自动消失。错误类不自动消失。 |
| **EmptyState** | 线描插图（可复用 `PaperLineArt`）、16px 标题、一句说明、一个主操作。 |
| **Skeleton** | 加载占位用 `surface-sunk` 加微弱的光泽动画，替代空白或纯文字的「加载中」。 |

## 7. 交互与可访问性

- **对比度**：所有文字和背景的组合达到 WCAG AA，正文 ≥ 4.5:1，大字 ≥ 3:1。三个主题都要逐一校验 `ink-faint` 和状态色。
- **焦点**：只用 `:focus-visible`，统一样式为 `outline: 2px solid var(--color-accent); outline-offset: 2px;`。
- **点击区域**：可点元素至少 28×28px，图标按钮默认 32×32px。
- **不只靠颜色**：状态、批注类型、对照表的单元格状态，都要同时有图标、文字或线型的区别。
- **键盘**：保留现有快捷键（`Ctrl/Cmd+F`、`Ctrl+Shift+M`、`Esc`、`Alt` 轮盘），新增 `Ctrl+\` 折叠侧栏、`Ctrl+.` 开关检查器。悬浮提示里显示快捷键。
- **悬停态**：一律用 `surface-hover` 换底色，不用位移或放大。
- **滚动条**：保留现有的细滚动条，滑块颜色改用 `line-strong`，悬停时改用 `ink-faint`。
