# ReadX Windows 版

React + Go + Electron 的本地阅读与研究工作区。

## 运行

需要 Node.js 22.8+、Go 1.27+；Go 工具链可由 `CBCT_V2_GO` 指定。

```powershell
cd windows
npm install
npm run build
npm start
```

开发模式使用 `npm run dev`。双击启动器或 `npm start` 会检查源码指纹，仅在源码变化或构建产物缺失时编译；平时直接启动。PDF 阅读器、AI 设置等模块按需加载。全新克隆可直接启动，不需要旧版代码、队列或论文数据。旧版数据的兼容导入入口仍在书库左下角，原 JSON 文件只读。

工具链脚本会查找本机 Go，并默认使用 `https://goproxy.cn,direct` 模块代理；SQLite 使用纯 Go 驱动，不需要 GCC。单独构建后端使用 `npm run build:go`，单独运行 Go 测试使用 `node scripts/go.mjs test ./...`。

### 桌面快捷方式

```powershell
npm run shortcut            # 建立/修复桌面 ReadX 快捷方式（Electron 桌面壳）
npm run shortcut -- --browser  # 改用 start-browser.ps1 的浏览器回退入口
```

图标会先复制到 `%LOCALAPPDATA%\ReadX\ReadX.ico` 再写进快捷方式。仓库目录若被放在低完整性标记的位置（例如某些沙箱或测试目录），资源管理器会拒绝读取那里的 `.ico`，快捷方式就退回成通用图标；复制到本机应用数据目录可以避开这个问题。已存在的快捷方式只补图标和描述，不改动它原本启动的命令。

浏览器回退入口每次启动都会先增量构建 Go 服务，再用 `/v1/meta` 里的构建指纹比对正在运行的实例：指纹不同就停掉旧后端再起新的，不会因为「同一数据根已有服务」而复用一份过期后端。旧实例的窗口需要手动关掉或刷新一次。

## 新增阅读功能

- **PDF**：PDF.js 原版页面、可选文本层、缩放与适合宽度、原文件目录、页码导航。支持原 PDF 内置的引用与文内链接；没有内置链接时，可点击方括号数字引用，按参考文献列表定位到对应条目，并用“返回引用处”回到正文。后台逐页提取正文供问答使用；翻译由 OCR 排版链路负责，没有文本层的页面明确提示，不生成伪 OCR 正文。
- **论文标题目录**：优先使用完整的原书签；缺少章节目录或只有文章名时，从正文补充数字、罗马数字及常见未编号标题。保留原目录层级，并补充标题位置。点击目录定位到对应页内标题并高亮；过滤作者页眉、图表标签与参考文献条目。识别依据文本层及排版，扫描页需先 OCR。
- **面板边界**：目录和助读侧栏可拖动边界调整宽度，拖至边缘收起；双击分隔条恢复默认宽度，方向键微调。宽度在本机保存，窗口变小时自动给正文留出空间；原文与译文分隔条也可拖动。
- **五重奏精读**：阅读页的“精读五重奏”入口展开完整工作区，提供实验动机、方法公式、实验配置、结果分析、代码复现五步。支持逐节生成、顺序生成剩余项、取消、摘录与页码核对、笔记追问和 Markdown 导出；顶部导航提供独立 PPT 工作区，可选择论文并基于已保存记录导出 16:9 演示稿。PPT 先通读全文，再按六种学术版式编排重点、对比、流程、图文证据、数据和核心观点；原图等比嵌入对应论证，宽表与长内容自动分页。预览和导出共用布局，可通过缩略图逐页查看；完整来源保留在讲者备注中，中英文使用微软雅黑、数字使用 Times New Roman。页面规划使用 ReadX 内置的 `baoyu-slide-deck` 本地 skill，通过当前配置的 AI 渠道调用，不依赖模型提供商原生支持 skills；PPTX 仍由 ReadX 本地引擎生成。AI 观察实际图表裁图并结合原文统一归类，将原图、观察与解读嵌入对应步骤和小节；图表随本节生成自动插入正文；已有笔记可重新生成更新。界面展示缺失、降级和核验提示；无法核验的重新生成结果不覆盖原记录。结果分析保留原表，确认协议一致后可计算同列差值。代码复现区分论文事实、分析与核对行动，可保存为复现任务清单并核对源码快照。旧版记录仍可读；没有源码时只作复现计划。
- **AI 助教工作区**：采用 Figma 中的 Codex 风格布局，支持按文献保存多个本机对话、停止、重新回答、复制、公式与代码排版、出处跳原文。在输入区选择 Codex 模型及其支持的推理强度，自动保存并用于后续对话和精读；目录来自本机 Codex Desktop，无需另装 CLI。中断或失败的回答不进入后续上下文。工具栏的「AI 助教 ↗ / 精读五重奏 ↗」进入整页工作区，再点一次不会把它收起；「返回原文 ↙」或 Esc 回到并排阅读。
- **图表与公式**：按空间位置识别双栏/跨栏图注，结合矢量图形、图像面板和空白边界，从原 PDF 以最高 5 倍倍率裁切（受像素上限约束）。可切换本步骤、全部图表和待确认选区，并提示正文提及但尚未定位的编号。支持重新识别、原页拖框校正、补选遗漏项、忽略误识别候选及恢复；人工选区按文献保存在本机，不改原 PDF。待确认或裁切失败的选区不会加入精读图表目录。没有文字层的页面可手动补选，不把整张扫描页或任意图像对象冒充完整图表。方法公式以 LaTeX 源码保存并排版显示，可展开查看源码；应用界面的数字字形使用 Times New Roman。
- **EPUB**：按 spine 顺序读取章节，展示标题、段落、列表和文档内静态图片；可调整字号与字体、切换主题。EPUB 批注记录章节资源和字符范围，不冒充 PDF 页码。
- **位置恢复**：PDF 保存页码，EPUB 保存章节；重新打开文档恢复到上次位置。
- **选区批注**：鼠标拖选原文后，可添加高亮、下划线或问题批注，填写笔记、颜色与标签；右栏支持修改、筛选、定位和 Markdown 导出。也可将选段带入 AI 提问草稿。
- **双语阅读**：Windows 导入由 ReadX 提供入口，实际 OCR、段落归一化、全文翻译/修复及首轮 PDF 排版调用随仓库内置的 Lee `provider-case`。需要在 AI 助手设置中配置 PaddleOCR 与翻译模型；Codex CLI 配置会通过本机回环桥接供 Lee 调用。Lee 产出的 `document.v1`、逐页译文和译文 PDF 保存进 ReadX 文库，打开阅读器可直接查看。旧文档仍可按页生成 OCR 译文。译文字号可单独调整为 90%–120%，原文缩放保持独立；窄窗口工具栏横向滚动，原文和译文页面起点对齐。可切单栏或双栏、调整分隔线和交换左右。
- **段落操作**：PDF 原文的段落识别直接使用 Lee `document.v1` 归一化后的块与坐标，不再用 PDF.js 重新切段；悬停显示段落边框、点击段落或通过下拉列表选择，再带原文及页码提问。EPUB 可点击原文章节段落。段落翻译已并入 OCR 排版链路，段落浮窗不再单独调用模型；提问面板保留段落上下文，可输入具体问题，也可直接发送以解释该段。翻页或按 Esc 关闭段落浮窗，拖选文字仍可批注。
- **翻译引擎**：Windows PDF 导入运行 Lee 原生 Python 翻译链与修复流程，不再用 ReadX Go 代码仿写翻译。实现边界和数据回填说明见 `implement-stage/TRANSLATION_ENGINE_NOTE.md`。
- **译文 PDF 导出**：阅读工具栏“导出译文 PDF”把原 PDF 与译文交给 Lee 的 RPR 排版引擎（随应用内置，MIT）重新排版，再叠回原 PDF，保留页尺寸、栏位、图表与公式位置。可选当前页或全部页面；页眉页脚、作者/单位、参考文献和公式/表格/图片保持原样。扫描件可配置 PaddleOCR 文档解析（令牌只存本机 `app/config.json`）先识别版式再走同一渲染链。引擎与字体资源见 `resources/README.md`。

### OCR 服务选择

在「AI 助手设置 → 文档识别」选择 **PaddleOCR** 或 **MinerU**，填写对应服务的访问令牌，再点击「保存 OCR 设置」。两家服务的地址、模型和令牌分别保存在本机配置中，切换时不会混用。

MinerU 接入[官方远程解析 API](https://mineru.net/apiManage/docs)，支持 `vlm` 和 `pipeline` 模型，每份 PDF 最多 200 MB、200 页。导入、重新识别和阅读器的 OCR 版式回填均使用所选服务；后续翻译和 PDF 排版沿用 Lee 引擎。

## LaTeX Studio

顶栏「LaTeX」是与书库并列的独立写作工作区，读写磁盘上真实的 `.tex` 文件，不影响书库记录。

- **需要本机 TeX 发行版**：ReadX 不内置 TeX，也没有把 TeX 打包进安装包。请在系统里安装 MiKTeX 或 TeX Live（中文文档建议一并装 XeLaTeX）；装完若 ReadX 已在运行，可在编译面板点「重新探测」，不必重启应用（应用启动时才继承 PATH）。
- **编译方式**：本机 `latexmk` 实测可运行时优先用它；不可用时用内置多趟（引擎 → 需要时跑 bibtex/biber → 交叉引用重跑，最多六趟）。哪个引擎可用、哪个不可用及原因，都在编译面板如实列出——例如 `latexmk.exe` 存在但缺 Perl 时会这么写明并说明已改用内置多趟。
- **文件位置**：项目源码在数据根下的 `latex-projects/<项目编号>/src`，每次编译的产物在同项目的 `build/<编译编号>`，每个项目保留最近 10 次。可以直接用外部编辑器打开源码目录；在 ReadX 之外改动文件后，编辑器里保存会提示冲突并让你选择「重新加载」还是「以我的版本覆盖」。
- **本机编辑与编译**：文件编辑、编译与 PDF 预览在本机完成；调用 AI 问答或修改时，相关 `.tex` / `.bib` 上下文会发送给所选模型。「导入 ZIP」解压到项目目录，并拒绝 `..`、绝对路径、符号链接等越界条目。
- **诊断敢说实话**：每条诊断都标注来源（LaTeX / Package natbib / Class IEEEtran…）。位置只有两种可信来源——日志行直接给出的 `file:line`，或在项目源码里找到那个引用键（`\cite`/`\ref` 的键）；日志没给位置的整篇级警告（例如 `lineno` 的 “Line number reference failed”）就显示「日志未给出位置」，不再按「最近打开过的文件」硬猜一个。诊断列表就是最后一次编译那份日志（与「N 个警告」同源），不会把同一批问题按趟数重复报出来。
- **多趟编译与「续上上一次」**：TeX 说「再跑一趟」就再跑（上限 6 趟，普通文档 2~3 趟就结束）；需要时自行跑 bibtex/biber。新一次编译会把上一次构建目录里的**辅助文件**（`.aux`/`.bbl`/`.toc`/`.brf`…）搬进新目录，但**绝不搬上一次的 PDF 与日志**——交叉引用、目录、评审模式的页边行号（lineno）都依赖上一趟的 `.aux`，没有它就只能永远停在 “re-run to get it right”，页边行号也就可能是错位的（实测一份真实 CVPR 评审模板：沿用辅助文件后第一次编译即 0 警告，页边行号连续正确）。
- **对话内确认修改**：直接发送「把 abstract 里的数字删掉」等要求，助手会结合当前编辑内容和项目内 `.tex` / `.bib` 上下文定位文件，在回复下展示修改卡片。卡片可展开查看修改前后内容；点「确认修改」才创建快照并保存，点「取消修改」不写入。输入栏显示「请求批准」，每次修改单独确认，无需另点预览按钮。每张卡片修改一个文件，保存前会核对内容，拒绝覆盖生成期间的新编辑。
- **编译修复与源码快照**：这一区域默认折叠，可展开生成修复建议、查看快照并回滚。单独使用自动修复时，先开启工具栏的「自动修复写入」；自动修复按「快照 → 写入 → 真实编译 → 错误未减少则回滚」执行。聊天修改仍逐次确认。手动回滚会恢复快照时刻的源码，之后新增的文件会被移除并列出；编译修复日志在服务端脱敏后才发送给模型。
- **可调整的布局**：项目目录支持拖拽加宽，字号更大；诊断列表可隐藏，无错误或警告时不显示空提示，给 PDF 预览和对话留出空间。
- **AI 渠道**：在 LaTeX 助手面板点「模型设置」，可跟随全局或单独配置 HTTP 提供方、API 地址、模型和推理强度。模型列表支持拉取、搜索和选择，保存后同步显示在助手标题与输入栏。密钥按「渠道 + 地址」隔离，独立配置不影响阅读与翻译渠道；CLI 渠道的可用性取决于后台运行环境。

## 摸鱼界面

点击顶部挂件，通过淡绿色漫画窗帘切换科研与摸鱼界面：平涂色块、描边褶皱、扇形帘头和少量网点，呈现纸上漫画的质感。挂件可沿顶部拖动并记住位置；`Ctrl+Shift+M` 快速切换，摸鱼界面按 `Esc` 返回。

摸鱼界面还带三样小东西：书架顶部的**摸鱼周报**（本周时长、读完章节/页数、连续天数）；「小游戏」里的 **2048**（方向键 / WASD / 滑动，进度与最佳分自动保存）；以及顶部可拖动的**下班倒计时**小牌（距下班 / 周末 / 元旦，点开可改下班时间或收起）。

## 导入文档

首次在 Windows 开发目录运行 PDF 导入前，执行 `powershell -ExecutionPolicy Bypass -File windows/scripts/setup-retain-runtime.ps1`。脚本把 Lee 所需 Python wheel 安装到 `windows/.retain-runtime`（E 盘工作区内），只接受预编译 wheel，不需要安装单独的翻译引擎桌面端或 C/C++ Build Tools。桌面端上传/导入入口不变。

顶部“导入 PDF / EPUB”支持文件选择、多文件导入与拖放。每次最多 16 个文件，合计不超过 100 MB；按文件内容哈希去重，重复导入保留既有批注。

PDF 文件、推荐卡片与链接下载统一在 OCR 后识别题目、作者、DOI 和中文题名，并以标题或 DOI 联网检索 OpenAlex / Crossref。AI 设置中的助手核对原文与搜索题录，再补齐缺失的期刊/会议及年份；已有题录保留，搜索或核对未完成时显示提示，未知字段留空。缺少出版信息的旧论文重新导入时，也会复用既有正文联网补齐，保留批注及翻译结果。联网检索会发送论文标题或 DOI，首页文本与候选题录会发送给所选 AI 渠道。原文入库后，全文翻译、排版与论文记忆在后台继续；可在任务面板查看进度或重试。

导入面板实时显示当前文件及序号、解析页数、上传字节数、翻译段数和当前批次、保存阶段、总用时及带时间的处理记录。进度条表示当前阶段的实际工作量；AI 识别等无法计量的阶段显示等待动画，服务每两秒发送连接消息，不以等待时间冒充完成百分比。下载公开全文期间显示下载阶段和用时，服务返回文件后显示接收字节进度。可随时取消，已完成导入的论文保留，未完成的当前论文不会生成条目。

联网导入支持公开的 PDF/EPUB 直链、arXiv 编号或链接、DOI，以及按标题检索后选择全文。元数据查找使用 OpenAlex，并以 Crossref 作为备用来源。界面显示下载、排版解析与 AI 处理阶段，可随时取消；arXiv 主地址失败时尝试官方 export 地址。出版方要求登录或未提供全文链接时，可选择本地文件导入。

## AI 接入

在顶部“AI 设置”选择渠道、保存配置，再点击“保存并测试连接”。测试会向所选服务发送一条简短文本请求。

| 渠道 | 配置 |
| --- | --- |
| OpenAI 兼容 API | 地址（例如 `https://api.openai.com/v1`）、服务支持的模型名、API Key |
| Anthropic Messages API | 地址（例如 `https://api.anthropic.com/v1`）、模型名、API Key |
| Codex Desktop / CLI | 自动识别 Codex Desktop 自带程序，或 PATH 中的 `codex`；先在桌面版登录即可 |
| Claude Code CLI | 在 PATH 中安装 `claude`，先运行 `claude auth login` |
| Kimi Code CLI | 使用支持 `--agent-file` 的当前 Kimi Code CLI，先运行 `kimi login` |

CLI 模型可留空以使用其默认值。程序通过官方 CLI 使用已有登录状态，不读取凭据文件，也不实现 OAuth。CLI 在临时目录运行；Codex 使用只读沙箱并关闭 shell，Claude 关闭内置工具和 MCP，Kimi 使用无工具的阅读 Agent。标准输出只提取助手回答，进程失败或取消不作为完整回答处理。

Windows 下会自动扫描 `%LOCALAPPDATA%/OpenAI/Codex/bin/*/codex.exe`，更新后无需手动修改版本路径；也可用 `CBCT_CODEX_PATH` 指定程序。AI 设置会显示是否来自桌面版及登录状态，无需再填 API Key。调用会优先使用已有代理环境变量，否则读取 Windows 当前手动代理。临时文件与运行日志放在应用数据目录的独立请求目录，结束后清理。服务可执行文件按内容指纹缓存在 `%LOCALAPPDATA%/CBCTReading/runtime/` 后运行，避免工作区继承的低完整性标签使 Codex 无法初始化；论文、设置与数据库仍使用原数据目录。

问答、翻译和 PDF 精读生成共用所选渠道。API Key 存放在本机 `app/config.json`，不回传界面；不同渠道和地址分别保留 Key，切换地址不会发送其他地址的 Key。原配置中的其他字段保留。

## 数据与范围

文件保存在数据根的 `library/`，SQLite 位于 `app/data/v2/reader.db`。新增迁移只增加列与表；已有 PDF、精读记录和批注保留。服务仍只绑定回环地址并校验 bearer token，联网导入拒绝私网地址，EPUB 不执行脚本或远程资源。

文章卡片右上角的垃圾桶将条目移入回收站，可恢复；列表和表格也提供同样入口。回收站右上角可“清空回收站”，确认后永久移除条目及关联批注、译文、精读、阅读位置和复现记录，并删除 `library` 文件夹中未被其他论文引用的导入副本；原始位置的 PDF/EPUB 文件保留。回收站界面显示当前导入副本的实际目录。

当前支持无 DRM 的可重排 EPUB 和可由 PDF.js 打开的 PDF。EPUB 采用安全重排，未保留出版方完整 CSS、固定版式或复杂 SVG 布局；MathML 仅保留文本内容。扫描 PDF 通过已配置的 PaddleOCR 处理；支持从本机 Zotero 7+ 批量导入 PDF；需在 Zotero 高级设置中启用应用间通信。密码输入和浏览器采集扩展尚未提供。CBCT 实验配置与结果校验仍面向 PDF，EPUB 提供阅读、批注、翻译和基于章节的问答。

## 开发结构

### LaTeX 实时预览

LaTeX Studio 工具栏新增“实时预览”，基于 [realtime-tex（rtex）](https://github.com/HenryXiaoYang/realtime-tex) v0.0.5。项目需要使用 LuaLaTeX；其他引擎的项目可在面板内切换。首次预览会排版整篇文档，后续正文改动直接更新段落，分页、引用和复杂图形由后台整页排版更新。面板显示段落耗时、整页同步状态和可跳转的 LaTeX 诊断；复杂页面使用 PDF 回退并标明状态。

本机需要 MiKTeX 或 TeX Live 中的 LuaLaTeX。面板可下载并安装官方 rtex 发行版，安装前校验固定 SHA-256，运行时位于 `<数据根>/app/runtime/rtex/0.0.5/`。自定义安装可设置 `READX_RTEX_BIN` 指向 `rtex` 可执行文件，并保留发行包的 `share/rtex/tex` 目录（也可设置 `RTEX_TEXDIR`）。打包时包含 Node 桥接程序和上游 MIT 许可证，rtex 引擎按需下载。普通编译及 PDF 导出仍通过现有编译功能使用。

`apps/server` 管理文件、SQLite、导入和 AI；`apps/web` 提供书库与阅读界面；`apps/desktop` 管理 Electron 窗口和服务进程；`packages/shared` 维护 API 类型；`scripts` 管理构建和开发编排。前端构建会从 PDF.js 依赖复制 CMap 与字体资源，生成目录不进入 Git。

服务 stdout 的 `CBCT_V2_READY ` 前缀用于就绪协议，日志走 stderr。Electron 通过 preload 注入 token；浏览器开发模式由 Vite proxy 补鉴权头。服务使用 `--exit-on-stdin-eof` 随父进程停止；HTML 下发 CSP，Electron 保持 sandbox 与 contextIsolation。

## macOS 与共享实现

macOS 已使用同一套核心源码，平台安装、打包和验证说明见 [`../macos/README.md`](../macos/README.md)。核心代码以 Windows 工程为编辑入口；修改后运行 `node ../scripts/sync-platforms.mjs`，CI 会拒绝两端受管源码不一致。服务意外退出会在一分钟内最多重启三次，正常退出不再触发服务异常弹窗；重启不自动重放中断请求。

### 无 AI / OCR 配置时阅读原文

在导入窗口勾选「仅保存原文」，再将文件队列单篇或批量导入。此模式保存 PDF 原文件及已有题录，不调用在线 AI、OCR 或题录服务；没有题录时暂用文件名。入库后可阅读、批注，阅读器会为有文字层的 PDF 补建正文索引；扫描件不自动识别。配置服务后，可在阅读器中点击「重新翻译」执行 OCR 和翻译，保留同一书库条目。链接搜索与下载仍需联网。

### 完整备份与恢复（开发中）

书库同步设置中新增「创建完整备份」和「从备份恢复」。操作确认后关闭应用，完成后自动重启；同时保存数据目录与桌面本地存储，恢复前校验文件并保留原目录检查点。详见[备份与恢复说明](../docs/backup-and-restore.md)。
