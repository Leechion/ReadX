## 2. 授权执行约定

新书库和没有策略记录的旧书库默认 `ask`，已有 AI／OCR 配置不视为发送同意。规则值为 `ask`、`deny`、`allow`；参与请求的任一范围为 `deny` 即拒绝，任一为 `ask` 即要求确认。因此整库允许时仍可单篇拒绝，整库拒绝不能被单篇允许覆盖。

首版覆盖导入／下载、OCR 重翻、AI 对话／精读／演示稿／LaTeX 助手、图谱抽取、文献发现、引文目录、书源、同步及新增分享／Zotero 写接口。原文仅本地保存、已有正文阅读和本地笔记接口继续可用。同步按整库检查；任一论文拒绝时会阻止本次同步，不会悄悄只同步一部分。

确认流程：业务请求先获得 HTTP 428 的处理说明 → 用户确认 → 本机批准接口 → 原请求带一次性票据重试。票据绑定请求内容、当前配置和文档／项目上下文指纹、策略版本与到期时间。Multipart 的随机边界不影响同一文件重试；重复 metadata 和过大字段会拒绝。链接导入拿到 PDF 后还会按内容哈希复查单篇拒绝规则，再进入 OCR／题录补全。

策略改变会取消旧授权上下文并清空未消费票据；不能撤回此前已经成功发送的数据。CLI、模型代理和渲染器中的任意网络行为没有获得系统级隔离，也不能据此承诺数据不出境。界面不宣称内容已脱敏。

授权日志接口为 `GET /v1/processing/audit`，需要本机 Bearer 鉴权，只记授权决定和对象标识，不保存正文或密钥。日志不等于外部服务已收到，也不等于处理成功；首版暂无日志管理界面。

持久策略随本机数据库保存；一次性票据、Zotero 写授权只保留在进程内，不序列化进分享。现有跨设备同步采用明确的业务实体列表，不会同步这些新增策略或票据。完整备份恢复可能恢复持久策略，恢复后重新确认规则尚待实现。

## 3. 外部数据流清单

| 操作 | 发送范围 | 接收方／边界 |
| --- | --- | --- |
| PDF OCR／翻译／重新处理 | 原 PDF、识别正文、翻译上下文、题录、模型任务输入 | 配置的 OCR 与 AI 服务；连接到本地代理也不代表代理不联网 |
| 精读／问答／图谱／演示稿 | 选定文献上下文、用户输入、对话历史、附件图片、精读结论／图表说明等，依操作而定 | 当前模型服务或本机 CLI；CLI 的后续服务无法精确列举 |
| LaTeX 助手 | 当前未保存缓冲区、项目内 TeX／Bib 上下文、问题及相关日志 | 独立 LaTeX 模型配置或 CLI |
| PubMed／OpenAlex／Crossref 检索、引文查询 | 当前检索式、DOI、目录标识、页码 | 对应目录服务；不因检索而上传完整 PDF |
| 来源链接下载、外部书源 | 来源 URL、目录查询、书源所需凭据 | 来源站点／书源服务；失败仍由现有导入接口报告 |
| 跨设备同步 | 现有同步定义的文献、附件、批注、进度等 | 配置的文件夹／WebDAV；不能按“当前选中文献”理解 |
| 浏览器采集 | 用户点击的当前页来源及页面题录元信息 | 先只进本机收件箱；不向扩展传递 ReadX Bearer Token，不读取 Cookie／浏览历史 |
| Zotero 回写 | 当前确认的笔记文本、父条目标识、对象版本 | 本机 Zotero；Zotero 自身可能随后同步上传 |
| 只读分享 | 所选题录和显式勾选的内容 | 本机生成 HTML，接收者由用户自行选择；不经过 AI 服务 |

外部接入依据核对了 [Zotero 本机 API](https://www.zotero.org/support/dev/web_api/v3/local_api) 和 [OpenAlex 当前认证说明](https://help.openalex.org/api/authentication/)。OpenAlex 无 Key 调用属于有限额度，首版没有新增其 Key 配置入口；服务返回的鉴权／限流／不可用错误会保留在逐源记录，不能承诺持续大规模检索。
